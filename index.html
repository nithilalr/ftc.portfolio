ITERATION 01 // INTAKE

Vectored Wheel Intake

In this iteration we moved the intake rollers over to vectored wheels, so the angled rollers pull game pieces in more smoothly and keep them from getting stuck or misaligned at the mouth of the intake. Fig. A shows the printed pair; Fig. B shows the parts that make up each wheel — the hub and the individual rollers that press into its circumference.

The wheels came out slightly too large to seat cleanly inside the intake design, so the fitment is being adjusted before the assembly goes back onto the robot.

Figs. C and D are the CAD and build-floor verification side of the same iteration — reviewing the assembly in Onshape and checking the printed parts against the model on the build floor.

ITERATION 02 // SHOOTER

Shooter Iteration

What We Had: Our original robot used an existing baseline shooter design that had noticeable flex during high-speed launches.

What We Changed: We designed and 3D-printed a new rigid shooter structure (Fig. A) across three CAD layout revisions (Figs. B–D), stiffening the frame to reduce unwanted movement and improve shot accuracy.

Problem: The new shooter assembly came out slightly too large to fit cleanly within our robot's mounting envelope.

public void runOpMode() {
  drive.followTrajectory(toSample);
  while (opModeIsActive() && !claw.hasSpecimen()) {
    claw.extend();        // closed-loop PID
    if (vision.targetLocked()) break;
  }
  claw.retract();
  drive.followTrajectory(toHighBasket);
  lift.toPosition(HIGH_RUNG); // 0.0 -> 1.0
  claw.release();
}
